# UI & Display Preferences

- Prefers data tables to list rows in FIFO (first-in-first-out) / chronological date-wise order — the entry that came in first appears first (oldest date first, newest last), matching the underlying business logic (e.g. stock lots ordered by inward date rather than alphabetically by material name). Confidence: 0.6
- Favors minimal, client-facing UI: show only the key figures the client needs at a glance (e.g. available quantity and weight) and drop verbose/descriptive text — long material-type labels, "next FIFO lot" hints, and other secondary notes should be removed. "Keep simple to see client in UI." Confidence: 0.75
- Dislikes plain/"boring" flat tables and grey surfaces; wants visually engaging, colourful UI that users enjoy working in — e.g. coloured status badges/counts on filters, colour-coded rows, and coloured filter chips rather than bare grey controls. Confidence: 0.85
- Wants a visual/formatting treatment applied consistently across the whole site, not just the one page they pointed at — reuse shared components so every register gets the same look. Confidence: 0.8
- Prefers "the row itself is the button": clicking anywhere on a table row should open that row's related form/dialog, instead of a separate per-row action button in an Action column (e.g. the blue "Enter Qty" button). Only rows with work actually to do should be interactive; finished rows should be inert so the pointer signals where there's work. Confidence: 0.7
- Wants status-badge colours to carry fixed, consistent semantic meaning and be applied identically on every table/page (e.g. "Pending" should be a red badge everywhere). Confidence: 0.7
